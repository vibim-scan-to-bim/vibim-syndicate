Project 368.CAN: Technical Reference

Reference notes for a Revit modeling project on an office complex in Canada.

Specification

Item Value
Project code 368.CAN
Location Canada
Industry Office building
Client profile Confidential
Total area 10,000 m²
Floors 4 basement levels, 9 upper floors
Level of development LOD 300
Inputs Point cloud, 2D CAD, TrueView
Deliverable Revit file
Software Revit, Navisworks, internal tools

Disciplines modeled

  • Architecture, including interior and exterior of the main building
  • Structure
  • Topography, on the right side of the building
  • MEP: ventilation, electrical, plumbing, fire protection, cable trays

The model also covers adjacent buildings on the left side and an extensive basement area. The purpose is to support future management, planning and renovation design.

Definitions used on this project

  • Point cloud: a set of scanned points describing existing geometry. It was the primary reference for existing architecture and structure.
  • Workset: a Revit subdivision of the model that lets teams own and update areas separately. New worksets were created for newly scanned zones.
  • Parametric Family: a reusable Revit component whose size and properties are controlled by parameters. ViBIM used them for repetitive MEP objects.
  • LOD 300: the level of development targeted for all elements.

Workflow steps

  1. Set up Levels and Grids from the scan data.
  2. Link point cloud and CAD/PDF sources and place them in the project coordinate system.
  3. Split modeling by basement floor or smaller zone.
  4. Create a new workset for each newly scanned zone and assign an owner.
  5. Compare new and existing models in Navisworks to confirm workset allocation.
  6. Model MEP directly from the point cloud, cross-checking shop drawings and technical documentation.
  7. Run Navisworks clash detection together with the Revit modeling.
  8. Review through section reviews, Navisworks and point cloud analysis tools before handover.

Tolerance

The MEP model was built with a maximum deviation of ±15mm. It covers equipment, ductwork, piping and cable trays.

Known data limits

  • Basement point cloud quality was poor, which made existing ventilation hard to identify.
  • Coverage was incomplete in some areas, so component dimensions, material types and connections were hard to confirm.
  • Chiller plant rooms hold large duct shafts in confined technical boxes, which limited scan quality.
  • Dense cable trays and conduits in basements, rooftop and technical shafts complicated complete modeling.

Hardware

High-performance workstations and servers with high-speed SSDs and 64GB of RAM handled the large scan data volume.
