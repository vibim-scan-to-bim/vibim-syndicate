Project 498.UK: Technical Reference for the Revit Office Building Model

This page records the technical parameters, definitions and workflow of Project 498.UK, a Revit modeling job for an office building in the United Kingdom.

Specification

Item Value
Project 498.UK
Location United Kingdom
Building type Office building
Total area 13,000 m²
Floors 1 base level, 5 upper floors
Level of development LOD 300
Inputs Point cloud, TrueView
Deliverable Revit file
Software Revit, Navisworks, internal tools
Team 16 specialists
Period April to June 2023
MEP tolerance ±15 mm

Scope

  • Architecture, structure, topography and MEP modeling.
  • Exterior and part of the interior of the main building.
  • Surrounding topography.
  • Two facades of two adjacent buildings.

Definitions

  • LOD 300: a level of development where model elements have defined shape, size, location and quantity.
  • Point cloud: a set of measured points from a site scan, used as the geometry reference.
  • TrueView: panoramic imagery used to read the scanned space and verify objects.
  • Paint tool: the Revit function that applies a material appearance to a surface without changing geometry. The client required it so the model shows real exterior finishes.
  • Parametric family: a Revit object whose size and properties change through parameters. Here, families served MEP objects with similar shapes and sizes.
  • Registration: the alignment of scan data in a shared coordinate system.

Workflow

  1. Review inputs: point cloud, TrueView, PDF documents, exterior photographs.
  2. Estimate hours per MEP system from area, project type and past similar projects.
  3. Assign staff by system and zone, with daily supervision of new staff.
  4. Model architecture from the point cloud, photographs and reference documents; assign materials with Paint using Google Maps, photos, TrueView and existing data.
  5. Model MEP with two workstreams: vertical technical shafts and horizontal HVAC and MEP routes.
  6. Work in Revit and Navisworks in parallel.
  7. Run QA-QC: section checks, Navisworks validation, internal software checks.
  8. Correct errors found by QC, including client-identified and latent defects.

Known risk: registration error

At 80% completion, the client reported errors in point cloud registration. Comparison with the updated point cloud showed deviations in elevation, tilt angle and X-Y axis. Late changes to elevation and tilt can cause broken links, missing objects, position shifts and longer processing time. The response was a senior QA review of root causes, selection of correction methods and extra qualified staff.

Constraints on the input data

MEP inputs were limited to PDF documents and exterior photographs. This made estimates harder for false-ceiling access, object density and number of shafts. The point cloud also had overlapping points and coordinate misalignments, which required repeated adjustment in the basement, rooftop and shafts.
