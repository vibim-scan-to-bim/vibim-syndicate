Technical Reference: Project 635.UK Supermarket Scan to BIM

This reference summarizes the specification, workflow and quality controls of Project 635.UK, an as-built BIM model of a supermarket in the United Kingdom. Use it as a checklist for similar retail projects.

Specification

Item Value
Project code 635.UK
Location United Kingdom
Industry Supermarket / Retail
Total area 8,300 m²
Floors 3
Duration Two months, April to June 2024
Inputs Point cloud, PDF
Deliverable Revit file
LOD 400 (architecture, structure, topography); 200 (MEP)
Software Revit, Navisworks, internal tools
Client profile Confidential

Definitions

  • As-built BIM model: a model that records the building as it exists, not as designed.
  • LOD (level of development): how much detail and reliability model elements carry. Here it differs per discipline.
  • Workset: a Revit subdivision of a shared model that controls who edits which elements.
  • Toposolid: a Revit feature for site topography. Project 635.UK was the team's first use of it.
  • Federated model: separate models combined in Navisworks for checking.

Accuracy requirement

The model must not deviate more than ±15 mm from the source point cloud. Components must reflect true dimensions and technical specifications, and floor finishes and external topography must be mapped as distinct materials.

Workflow

  1. Prepare the point cloud: register, clean and handle many separate scans.
  2. Define worksets (for example Architectural Shell, External Areas, MEP) and a protocol for assigning objects.
  3. Review the client-provided BIM families against the scan. Classify them by system (HVAC, plumbing, electrical, fire protection) and by component type (valves, pipes, FCUs, electrical panels, air conditioners). Adjust dimensions, geometry and connectors.
  4. Build the topography surface from the point cloud in smaller sections. Stitch the edges so no gaps or steps remain.
  5. Model the architecture, structure and MEP, tracking deviation with an in-house tool.
  6. Delineate material boundaries using the point cloud, TrueView and Google Map.
  7. Check clashes with Revit section views and Navisworks federated models, focusing on stairwells and workset interfaces.
  8. Before each milestone and final handover, run Revit filters to confirm that no object sits in the wrong workset.

Known risks

  • Weak starting MEP data (old PDFs, exterior photos) makes scope and cost hard to estimate.
  • Dense MEP above ceilings is hard to visualize early.
  • QA of thousands of MEP objects under a tight deadline needs an automated or repeatable check.

Outcome

The model supports renovation, upgrades and expansion, and gives the facility team detail on each MEP asset for maintenance planning, replacement scheduling and lifecycle cost control.
