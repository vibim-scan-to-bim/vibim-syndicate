BIM Clash Detection Technical Reference: Definitions, Types and Process

This reference sheet collects the working vocabulary of BIM clash detection. It is meant for coordinators who need a quick lookup rather than a narrative.

Definition

Clash detection is the process of finding and resolving geometric interferences and spatial conflicts between components in a 3D building model. A clash occurs when an element from one model intersects with an element from another model, or violates its required buffer zone. Disciplines such as architecture, structure and MEP usually model separately, so overlaps appear when the models are combined into one federated, or master, model. Specialized software then analyzes that model and flags every instance where two objects improperly intersect or break predefined spatial rules.

Clash types

Type Also called Meaning Example
Hard clash Physical clash Two components occupy the same space A duct running through a concrete column
Soft clash Clearance clash A component lacks the buffer space needed to operate, be maintained or stay safe An air conditioning unit with no room for service access
Workflow clash 4D clash A conflict in schedule, delivery or site logistics Conduit work planned at the same time as a slab pour in the same area

A second soft-clash example from the source involves a high-voltage wire placed too close to a plumbing line, which creates an electrocution risk if the pipe leaks.

Traditional versus BIM-based detection

Factor Traditional BIM-based
Timing Found manually onsite during construction Found digitally before construction
Cost High rework, material waste and budget overruns Lower rework, fewer RFIs and change orders
Coordination Isolated teams working from 2D drawings Shared 3D model across disciplines
Decisions Reactive Proactive

Process reference

  1. Model preparation and aggregation. Collect the latest models, federate them in a coordination tool, set the required level of development and a common coordinate system.
  2. Preliminary checks. Inspect the federated model visually. Incomplete or poorly modeled elements cause false positives or missed clashes.
  3. Automated tests. Choose the models to compare, define clash type and tolerance, then run the analysis to produce a conflict list.
  4. Review and prioritize. Group results by status, location or system, rank them by severity and export a report with screenshots, element IDs and grid locations.
  5. Assign and track. Send each conflict to the responsible discipline and follow its status.
  6. Re-run. Update the native models, re-export, repeat the tests and continue until no interference remains.

Tool categories named in the source

  • Coordination and clash analysis: Autodesk Navisworks Manage, which merges many file formats and also supports 4D simulation and 5D cost estimation.
  • Authoring: Autodesk Revit with its built-in Interference Check, suited to preliminary checks only.
  • Cloud coordination: Autodesk Construction Cloud with its Model Coordination module, plus BIMcollab Cloud, Revizto and Trimble Connect.
  • Rule-based checking: Solibri Model Checker, which covers code compliance, model quality and accessibility rules.

Benefits at a glance

More accurate construction drawings, fewer onsite iterations, stronger interdisciplinary coordination, a more efficient project, more precise BOQs and BOMs, and reduced onsite risk through 3D visualization.
