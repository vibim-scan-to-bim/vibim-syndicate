Project 600.UK: Technical Reference for an MEP-Only Revit Model

Summary

Project 600.UK is an MEP modeling engagement for an office building in the United Kingdom. This page records the specification, the constraints and the working method in reference form.

Specification

Item Value
Location UK
Building type Office building
Modeled area 4,700 m²
Levels 4 basements, 13 upper floors (17 stories)
Discipline MEP only
Level of development LOD 300
Inputs Point cloud, PDF drawings
Deliverable Revit file
Software Revit, Navisworks, internal tools
Target tolerance ±15 mm

Definitions

  • MEP: Mechanical, Electrical and Plumbing systems. Here this covers mechanical, piping, ducting and lighting elements.
  • LOD 300: a level of development in which elements are modeled with specific geometry, size and location, based on actual construction details.
  • Point cloud: a set of scan points that records the existing building geometry and serves as the modeling reference.
  • Parametric family: a reusable Revit object whose size and properties are driven by parameters, used here for similar repeated objects.

Input constraints

  1. Architectural and structural elements were supplied, so no shell modeling was needed.
  2. At estimating time, only PDFs and exterior images were available.
  3. Basement point cloud quality was poor, which hindered identification of ventilation, plumbing and cable tray systems.
  4. Rooftop machine rooms and oversized shafts link to the basements through narrow technical ducts.

Method

  1. Estimate. Benchmark against similar projects. Analyse area, building type and MEP density. Estimate time per system (HVAC, electrical, plumbing).
  2. Split. Break the project into individual systems and give each system a distinct color.
  3. Model. Use parametric families for repeated objects. Assign shafts and linear systems to dedicated modelers who use internal tools.
  4. Coordinate. Integrate Navisworks clash detection with the Revit workflow.
  5. Review. Check with sectional views, Navisworks inspection and internal platform checks.
  6. Correct. Resolve every issue found in client QC, then run a final internal check before handover.

Verification checklist

  • Dimensional accuracy within ±15 mm
  • All components at LOD 300
  • Systems separated and color-coded
  • Clash detection run in Navisworks
  • QC findings closed before delivery
