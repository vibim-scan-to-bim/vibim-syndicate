Scan to BIM Software Reference: Categories, Formats and Selection Criteria

Scope

This reference lists the software categories used to turn laser scan data into a parametric BIM model, the tools commonly placed in each category, and the formats that move between them. It is a lookup sheet, not a ranking.

Definitions

Term Meaning
Point cloud A large set of measured points captured by a laser scanner
Registration Aligning separate scans into one shared coordinate system
Indexed format A point cloud file structured for fast display, such as RCP or RCS
Tolerance The allowed deviation between a modeled element and the scan
LOD Level of Development, the required detail of model elements

Format handoffs

  1. Native scanner data (Leica BLK or RTC360, FARO FLS) enters the registration tool.
  2. The registration tool exports E57, or RCP and RCS for Autodesk tools.
  3. The modeling tool links the indexed point cloud and builds parametric elements.
  4. The model goes to Navisworks as NWC, or to Solibri as IFC, for checking.
  5. Verity compares modeled elements against the point cloud inside Navisworks.

Selection criteria

  1. Hardware and data origin: the registration tool should read the scanner's native format to keep metadata intact.
  2. Discipline and deliverable: pick the modeling platform for the asset type and required LOD.
  3. Interoperability: test each handoff before committing to a stack.
  4. Cost against frequency: licensing and workstation costs weigh heavily when Scan to BIM is not a daily task. Occasional users may do better with an outsourcing partner.

Known limitations of the approach

Verity can take a long time on very large facilities. Solibri checks data, not dense point clouds. Cyclone carries a high licence cost and a steep learning curve.
