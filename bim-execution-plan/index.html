BIM Execution Plan Reference: Terms, Components, Types and Standards

This reference sheet condenses what a BIM Execution Plan (BEP) contains and how its parts relate to each other. Use it as a quick lookup when you prepare, review or respond to a BEP on a project that uses Building Information Modeling.

Definitions

Term Meaning
BEP BIM Execution Plan. A project-specific document that defines how BIM will be created, managed and shared. Also called a BIM Implementation Plan or BIM Project Execution Plan.
EIR Employer's Information Requirements. The owner's statement of what it expects from BIM. ISO 19650 formally calls it the exchange information requirements.
OIR / AIR Organizational and asset information requirements. They feed the exchange information requirements, which the BEP answers.
MIDP Master Information Delivery Plan. States what information the whole team delivers and when.
TIDP Task Information Delivery Plan. The same idea at the level of one task team.
CDE Common data environment. The shared platform where project information lives.

Pre-contract and post-contract BEP

Aspect Pre-contract BEP Post-contract BEP
Timing During tender, before award After the contract is awarded
Author The bidding supplier or design team The lead contractor with the full team
Purpose Show capability and respond to the EIR Confirm and fix the delivery workflow
Typical content Proposed approach and high-level standards Responsibility matrix, MIDP, TIDPs, detailed QA/QC

ISO 19650 uses the same split under different names: a pre-appointment BEP and a post-appointment BEP.

Components checklist

  1. Project overview and key milestone dates.
  2. Key project contacts and BIM roles.
  3. Project goals and the BIM uses chosen to meet them.
  4. Responsibility matrix.
  5. BIM process design (process maps).
  6. Information exchanges: model elements, level of development and level of information per milestone.
  7. Facility data requirements, often exchanged through COBie.
  8. Collaboration procedures, file structure and CDE.
  9. Model quality control.
  10. Technology, naming conventions and coordinate system.
  11. Deliverables and delivery strategy.

Build sequence

  1. Understand the project and the owner's requirements.
  2. Define SMART goals and BIM uses.
  3. Assign roles and the responsibility matrix.
  4. Set communication routines and the CDE.
  5. Develop the execution strategy for each phase.
  6. Select software and hardware.
  7. Set deliverables and a timeline.
  8. Establish quality control.

Maintenance rule

Treat the BEP as a living document. Review it at the start of each major phase, such as schematic design, design development and construction. Review it again when the scope, key personnel or software changes.

Common failure points

  • Vague objectives and scope.
  • A plan written without stakeholder input.
  • Unassigned roles.
  • Missing naming, exchange-format or QC standards.
  • A plan that is too complex or too rigid to adapt.
  • A plan copied from another project and never revised.
  • No QA/QC on models and data exchanges.
