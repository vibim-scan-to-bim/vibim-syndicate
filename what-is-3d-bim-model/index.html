3D BIM Model: Technical Reference

Definition

A 3D BIM model is a coordinated assembly of building objects that carry geometric and non-geometric information. It is produced during the 3D phase of the Building Information Modeling process. Its elements store geometry, properties and relationships, unlike a surface model that records shape only.

Conventional 3D model compared with a 3D BIM model

Attribute Conventional 3D model 3D BIM model
Basic structure Surfaces, meshes or solids Walls, doors, ducts, equipment as objects
Embedded information Optional metadata Structured parameters defined by the project scope
Relationships Not required Links to levels, rooms, systems and other objects
Change behavior Views may need separate updates Views and schedules update from the same object
Typical output Visualization, geometric reference Coordination, documentation, quantities, model review

Information bound to objects

Group Examples
Product identity Manufacturer, model reference, specification
Performance values Fire rating, U value, acoustic rating, load capacity
Spatial data Room areas, heights, volumes, containing space
Classification and status Uniclass or Omniclass code, project phase, existing, new or demolition status

Creation procedure

  1. Prepare the source. Confirm the design package for a new building, or register the survey data for an existing one.
  2. Set up the project. Define levels, grids, coordinates, naming conventions and required parameters.
  3. Model by discipline. Build architectural, structural and MEP objects in separate coordinated files.
  4. Federate and check. Combine the files, review alignment and data, resolve issues before delivery.

Common point-cloud inputs for existing buildings are RCP, RCS and E57.

Level of detail by stage

Stage Sufficient detail
Concept and feasibility Massing, floor plates, approximate openings
Design development Real element types, correct thicknesses, main services routed
Construction documentation Accurate sizes, locations, interfaces, penetrations, clearances
As-built record Verified against the survey

Level of Development states how reliably an element supports a stated use. A BIM dimension states which extra information is attached. They are independent: a concept model and a construction-documentation model can both stay 3D.

Delivery package

  • Native authoring file, usually .rvt.
  • Open exchange file, .ifc, with the schema named in the brief (IFC2x3, IFC4 or other).
  • Drawings cut from the model, .dwg or PDF.
  • Required object data, with an optional checked spreadsheet export.

Acceptance checks

  1. Geometry: correct levels, coordinates, hosts, no duplicates.
  2. Parameters: mandatory fields populated in the agreed format.
  3. Deviation: existing-building model compared with the registered point cloud, within tolerance.
  4. Scope completeness: every required discipline and category covered, exclusions recorded.
  5. Data consistency: naming, classification, units and formats uniform across files.

The signed project requirements remain the acceptance baseline. The ISO 19650 series frames information management, and the BIMForum LOD Specification helps define expected reliability. Neither replaces the agreed scope and tolerance.

Known limits

Source coverage, scope and LOD, parameter completeness, version control across discipline files, and IFC mapping differences between software can each reduce the reliability of a model for downstream use.
