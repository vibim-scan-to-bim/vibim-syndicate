Massive Point Cloud Datasets: Technical Notes

Working notes for handling very large laser-scan and photogrammetry datasets in AEC projects. A single scan of a large building or infrastructure asset can reach terabytes of raw data.

Core challenges

Challenge Effect Typical mitigation
Data volume Storage and transfer bottlenecks, transfers of hours or days on standard connections Compression, segmentation, hybrid storage
Data integrity Corrupted files, outdated versions, rework Versioning, access control, quality checks
Compute demand Slow performance, crashes, forced use of decimated data High-RAM workstations, GPUs, fast storage

Definitions

  • Registration: aligning scans captured from different positions or devices into one unified dataset.
  • Cleaning: removing noise, redundant points and outliers before modeling.
  • Classification: tagging points as floor, wall, pipe or conduit so a single system can be isolated.
  • Segmentation: splitting a dataset by floor, zone, discipline or construction phase.
  • CDE: a Common Data Environment, for example Autodesk Docs or Trimble Connect.

Formats

Format Role
RCP / RCS Autodesk indexed formats, optimized for Revit and Navisworks
LAS Standard for LiDAR data
LAZ Compressed, lossless version of LAS
E57 Vendor-neutral, stores point data and metadata

Processing steps

  1. Register all scans into one coordinate space.
  2. Denoise and filter outliers.
  3. Index the cloud in ReCap, RealWorks or Cyclone.
  4. Segment by floor, zone or discipline and classify points.
  5. Compress to LAZ or E57 for archive and hand-off.
  6. If the source format must be kept, split or archive the file (ZIP or RAR).

Exchange methods

Method Strength Limitation
Cloud or CDE Worldwide access, versioning, comments Bandwidth, recurring cost, restarts after an interrupted upload
Physical drive Independent of internet speed Loss, theft, damage in transit
FTP Low cost, resumable transfers No end-to-end encryption in standard FTP, no collaboration features
Local NAS Fast access on a local network Single location, upfront hardware and IT cost
Hybrid Local SSD for active work, cloud archive for finished data Needs automated sync and backup routines

Checks before modeling

Check registration quality and coverage first. Review the cloud for duplicate points, misaligned patches and gaps, since modeling on a flawed cloud only moves the error into the model. Keep the cloud segmented so each discipline loads only what it needs, and keep one agreed tolerance that follows the project specification and the scan quality.
