Scan to BIM Quality Control: A Technical Reference

This reference summarizes how quality control is organized when a laser scan is converted into a Revit model. It is written as a lookup sheet: definitions first, then the three phases, then the checks and tools that belong to each.

Definition

Scan to BIM quality control is the set of checks that confirms a 3D building model matches the point cloud it was built from. It covers geometry, coordinates, object classification and attached data. The goal is to catch errors before the model reaches design, construction or facility management teams.

Where errors come from

Risk What happens Typical symptom
Registration drift Individual scans are stitched together with a small misalignment Ghosting, doubled walls, shifted dimensions
Scan shadows Columns, furniture or equipment block the scanner Voids that the modeler must interpret
Noise Dust, people or reflections leave stray points Wrong pipe diameters, phantom objects
Interpretation A person converts points into objects Wrong LOD, unmarked assumptions
Data transfer Files move between registration, authoring and checking software Lost or corrupted information

Phase 1: before conversion

  1. Read the registration report and look for high mean error values.
  2. Inspect the cloud visually for ghosting and stitching faults.
  3. Remove noise with despeckle filters and segment out moving objects.
  4. Confirm the Survey Point and Project Base Point match the surveyor's grid or GPS data.

Phase 2: during conversion

  • Section boxes: cut thin slices through model and cloud together, then confirm walls, slabs and beams sit flush against the points.
  • Orthogonality and verticality: keep walls vertical and floors horizontal, but compare with the scan so real structural lean is not erased as noise.
  • View range isolation: limit View Depth and Top Plane to the active level so modelers do not trace the floor above or below.

Phase 3: after conversion

  • Ground truth check: compare model coordinates with survey control points.
  • Semantic validation: confirm a floor is a Floor and a door is a door. Rule-based checkers such as Solibri help here.
  • Deviation analysis: tools such as CloudCompare or Verity measure the distance from model surfaces to the cloud and draw a heat map. Green means within tolerance, red means outside it.
  • Clash detection: run hard and clearance tests in Navisworks or ACC.
  • Schedule checks: use Revit schedules to find empty parameters and duplicate elements.

Tolerance

Tolerance is set per project in the scope of work before modeling starts. Heritage and high-precision industrial work normally uses tighter limits than general architecture. A model should never be checked against a tolerance nobody agreed on.

Frequent mistakes

  • Trusting auto-extraction without human review.
  • Modeling from noisy points without checking panoramic photos.
  • Starting with the wrong origin or coordinate system.
  • Drawing hidden elements without labeling them as assumed.

QA versus QC

QA is process-oriented. It sets standards, workflows and training so errors do not occur. QC is product-oriented. It inspects the finished model and fixes defects. A project needs both.

Process at ViBIM

ViBIM applies a 36-point technical checklist and a two-layer review. The first layer is a self-check by the production team. The second is a specialist who is independent of the modeling team. The checklist covers geometric scope, naming and data structure, and model performance.
