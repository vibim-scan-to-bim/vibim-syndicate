Revit Family Creation: Technical Reference

This reference summarizes the building blocks of Revit family creation: definitions, family types, parameter scope, the six-step build and the standards used for review. It is written for modelers who need a quick lookup rather than a tutorial.

Definitions

  • Family: a group of elements that share a set of parameters and one graphical representation. Changing the family updates every instance.
  • Category: a broad group fixed by Revit, such as Doors, Windows or Walls.
  • Type: a specific size or variant inside a family. One door family can hold a 36" by 84" (914 by 2134 mm) type and a 30" by 80" (762 by 2032 mm) type.
  • Hierarchy: Category, then Family, then Type.
  • Family Editor: the Revit environment where loadable families are built from a template.
  • .rfa and .rvt: an .rfa is a loadable family file. An .rvt is the full project that loads and arranges families.

Family types

Type Where it is created Saved as Typical use
System Inside the project; cannot be exported In the .rvt Walls, floors, roofs, MEP systems
Loadable Family Editor, from an .rft template External .rfa Doors, windows, furniture, MEP equipment
In-place Inside one project only In the .rvt One-off, site-specific element

System families can be duplicated and adjusted but not built from scratch. In-place families suit a single unique condition, and overuse bloats the file and slows performance.

Parameter scope

Aspect Instance Type
Scope Each placed element All elements of the type
Edited in Properties palette Edit Type
Example Mounting height of one light fixture Door width, 36" (914 mm)

Rule of thumb: if two placed copies may differ, use instance. If they must match, use type. Past six preset types, move them into a type catalog (.txt) to keep the file light.

Six-step build

  1. Start from the correct template (Door.rft or Metric Door.rft). The template sets category and hosting.
  2. Draw a named reference-plane skeleton and set it equal with EQ.
  3. Model geometry (opening, leaf, frame) and lock every sketch line to a plane.
  4. Add parameters and formulas, for example Rough Width = Width + 2 x Frame_Thickness.
  5. Nest hardware as a sub-family and associate its parameters to the host.
  6. Load into a project, host it, flex it and check the swing.

Advanced techniques

  • Nested and shared families: a shared nested family can schedule and tag on its own.
  • Formulas: for example if(Length > 1500 mm, 3, 2) adds a third support leg past 1500 mm (59 in).
  • Visibility parameters: Yes/No parameters that switch parts on or off to control detail by view.
  • Dynamo and the Revit API: automate repetitive work when hundreds of families are needed.

Review checklist

  • Correct category and host.
  • Geometry modeled only to the required level of development.
  • Naming convention and a shared parameter file in use.
  • No hard-coded dimensions.
  • Flex test completed before delivery.
  • Geometry checked against the original point cloud when the family comes from a scan.

Standards referenced

ISO 19650, PAS 1192, AIA E202/E203 and the BIMForum LOD Specification.
