Point Cloud File Formats: Technical Reference for Scan to BIM

This reference summarizes the five point cloud file formats most often met in scan-based building projects: RCP/RCS, LAS/LAZ, E57, PTS and PTX. It is written as a lookup sheet, so each entry lists what the format is, how it stores data, and where it fits in a modeling workflow.

Definitions

  • Point cloud file format: a standardized structure for storing the three-dimensional coordinates captured by a scanner such as a LiDAR unit.
  • Proprietary format: a format created by one software vendor and tuned for that vendor's tools.
  • Open or vendor-neutral format: a format with a published specification that many programs can read.
  • Registration: the alignment of separate scans into one shared coordinate system.

Format summary

Format Structure Strength Limit
RCS / RCP Indexed proprietary binary; RCS is one scan, RCP is a project of many RCS files Fast display and handling in Revit, AutoCAD and Navisworks Intended for Autodesk software
LAS / LAZ Structured binary with a metadata header; LAZ is lossless compressed Classification codes, GPS time, intensity, color, coordinate system Large files for wide survey areas
E57 Binary data with an XML hierarchy, standardized by ASTM (E2807) Bundles points, panoramic images and scanner metadata in one file Heavier to produce than a bare point list
PTS ASCII text; a header with the point count, then one line per point Simple and widely readable Very large files, slower to process
PTX ASCII text organized by scan, with the scanner transformation matrix Keeps each scanner position, helpful for registration Large files, slower than binary formats

Reading the table

  1. RCS and RCP exist for performance. The spatial index lets software load only the points needed for the current view.
  2. LAS is the usual delivery format for airborne and drone LiDAR. Each point can carry a class code, for example ground, high vegetation or building.
  3. E57 is the format to pick when data moves between unknown software or has to be archived.
  4. PTS suits basic exchange when only the coordinates matter, with an optional intensity or color column.
  5. PTX is common as an export from terrestrial scanners, and it keeps every setup separate until registration.

Selection steps

  1. Identify the main application: survey data points to LAS or LAZ, while as-built modeling from terrestrial scans points to E57 or RCP/RCS.
  2. Identify the software: an Autodesk workflow benefits from RCP/RCS, and open-source tools such as CloudCompare or PDAL work best with LAS, LAZ or E57.
  3. Decide how the data will be shared: E57 is the safest choice when the recipient's software is unknown.
  4. Decide whether the dataset must be archived: E57 preserves the complete record.

Conversion notes

Converting between formats is routine, and CloudCompare handles most pairs. Going from a rich format to a simpler one can lose data. An E57 file converted to LAS loses its panoramic images, since LAS does not store them. Keep the richest original and derive the others from it.

Practical rule

Use PTX or the scanner's native format during registration, keep an E57 master, and prepare RCP or RCS for modeling. Confirm the formats with the receiving team before the scan starts.
